Mapa del sistema

Dónde va cada cosa en DownloadYTLocalWeb, y por qué.

Piezas

PiezaArchivoDecideCambia cuando…
Frontendfrontend/src/Qué ve el usuario; textos en español (messages.ts)cambia la interfaz
API HTTPmain.pyRutas, JSON, código HTTP de cada errorcambia el contrato con el navegador

Dependencias (imports)

server ──► main ──► downloads ──► analysis ──► links
  │          │          │             │
  └──────────┴──────────┴─────────────┴──► video_source   (no importa nada de la app)

Siempre hacia la Fuente de vídeo; nunca ciclos. Comprobar: grep -n "^from app" backend/app/*.py

Conceptos

Puerto
Lo que la aplicación necesita del exterior, como contrato. Aquí: VideoSource (un Protocol).
Adaptador
Una forma concreta de cumplir un puerto. Real: YtDlpVideoSource. De test: FakeVideoSource.
Fake
Doble de test que funciona de verdad pero simplificado (Fowler).
Inyección de dependencias
Pasar a una pieza lo que necesita en vez de que lo construya: create_app(video_source=…, clock=…).
Raíz de composición
El único sitio donde se montan las piezas reales: server.py.
Capa fina
Una capa que solo traduce (HTTP ↔ llamadas) y no contiene reglas: main.py.

Pregunta guía ante cualquier cambio

¿Por qué motivo cambia esto? → la pieza cuyo «cambia cuando…» coincida es donde va.
